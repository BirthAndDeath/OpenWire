# 常驻任务清单

用户指定任务编号时按顺序执行。未指定时按编号顺序逐项执行。

---

## 1. 审查仓库漏洞/codereview

对全部 Rust 源文件及非 Rust 文件进行安全审计，覆盖：

- **安全漏洞**：unsafe 代码、硬编码密钥、路径遍历、命令注入、时序攻击、密码学误用
- **性能瓶颈**：不必要的分配、同步阻塞异步、热路径大型分配、锁竞争、无界通道增长
- **逻辑错误**：off-by-one、unwrap/expect 可能 panic、竞态条件、死锁、状态转换错误
- **代码质量**：死代码、未使用导入、非惯用 Rust、复杂函数

输出格式：每个问题附 `{文件路径}:{行号}`、严重度（CRITICAL/HIGH/MEDIUM/LOW）、根因分析和修复代码示例。

---

## 2. 同步翻译

检查 `openwire/src/lib/locales/*.json` 下的多语言文件，确保：

- 所有语言文件 key 数量一致（以 `en.json` 为基准）
- 无缺失翻译（key 存在但值为空或与 en 相同）
- 术语一致性（如 `PeerID`、`ML-DSA`、`ML-KEM` 不误译）
- 新增 key 时同步更新所有语言文件

输出格式：缺失 key 列表、不一致术语列表。

---

## 3. 检查可优化项与配置安全性

### 配置检查

- `Cargo.toml`：依赖特性是否精简、`[patch]` 是否需要更新
- `tauri.conf.json`：CSP 是否严格、`dangerousDisableAssetCspModification` 是否关闭
- `capabilities/default.json`：权限是否最小化
- `.cargo/config.toml`：镜像源是否可用

### 代码结构检查

- `cargo clippy` 警告列表
- 公共 API 缺少文档的模块
- 可提取为独立子模块的过大文件（>800 行）
- 重复代码模式

输出格式：Clippy 警告列表、配置安全建议、模块拆分建议。

---

## 4. 更新依赖

### Rust 依赖

```bash
cargo update          # 更新 Cargo.lock 内的兼容版本
cargo upgrade         # 更新 Cargo.toml 内的主版本（需 cargo-edit）
cargo audit           # 检查已知安全漏洞（需 cargo-audit）
```

- 检查 `cargo outdated` 输出（需 cargo-outdated）
- 重点审计：`aws-lc-rs`、`libp2p`、`sqlx`、`tauri` 等核心依赖
- 验证 `cargo check` 通过

### npm 依赖

```bash
cd openwire
npm audit             # 检查安全漏洞
npm outdated          # 检查过期包
npm update            # 更新兼容版本
```

- 重点审计：`@tauri-apps/*`、`svelte`、`vite`
- 验证 `npm run build` 通过

### 补丁管理

- 检查 `patches/` 目录下的补丁是否适用于当前上游版本
- 上游发版后移除不再需要的 `[patch.crates-io]`

输出格式：更新前后版本对比表、安全漏洞摘要。

---

## 5. 自主优化 Plan

### 清理

- 删除 `plans/` 下已过时或被取代的 `.md` 文件
- 合并内容重叠的多个 plan 文件
- 归档已完成的阶段计划

### 优化

- 检查 `AGENTS.md` 和 `kilo.json` 是否需要更新命令或 agent 配置
- 检查 `.kilo/memory/` 中的记忆是否需要更新（过时决策、已修复的漏洞）
- 将多条分散的短 plan 合并为结构化文档

### 输出

- 删除/合并的文件列表
- 新增/更新的记忆条目
- 优化后的计划目录结构
