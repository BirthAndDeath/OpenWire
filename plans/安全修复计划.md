# OpenWire 安全修复计划

## 一、已验证漏洞清单（13 项确认，2 项误报排除）

### 复查结果

| 状态 | 数量 | 说明 |
|------|:----:|------|
| CONFIRMED | 13 | 真实安全漏洞，需修复 |
| FALSE POSITIVE | 2 | `request_file_download` 路径由 `resolve_download_dir` 沙箱化；`saturating_mul` 防止了整数溢出 |

## 二、漏洞详情与修复方案

### 2.1 高危 — 文件系统相关

#### S1: `send_file` 路径遍历 → 任意文件读取

- **位置**: `openwire/src-tauri/src/lib.rs:109-112`
- **风险**: `file_path` 未经任何规范化，可直接读取任意系统文件并发送到网络对端
- **利用**: 前端调用 `invoke('send_file', { file_path: 'C:\\Users\\victim\\AppData\\Local\\OpenWire\\keyring.db' })` 即可窃取密钥文件
- **修复**:
  ```rust
  let path = std::path::PathBuf::from(file_path);
  let canon = path.canonicalize().map_err(|e| format!("无效路径: {}", e))?;
  // 只允许发送 downloads 目录内的文件
  let downloads = self.downloads_dir().canonicalize()?;
  if !canon.starts_with(&downloads) {
      return Err("只能发送下载目录内的文件".to_string());
  }
  ```

#### S2: `validate_contact` 验证绕过（Fail-Open）

- **位置**: `openwire/src-tauri/src/lib.rs:55-69`
- **风险**: `storage::pool()` 返回 `None` 时，函数跳过所有验证直接返回 `Ok(())`，可向任意公钥发送消息
- **修复**:
  ```rust
  let pool = storage::pool().ok_or_else(|| "数据库不可用，无法验证联系人".to_string())?;
  // 验证逻辑...
  ```

#### S3: `delete_message` 无权限校验

- **位置**: `openwire/src-tauri/src/lib.rs:510-527`
- **风险**: 任何客户端可通过 `message_id` 删除任意消息，无归属检查
- **修复**: 增加 `owner_identity_id` 和 `peer_pubkey_hex` 匹配检查

#### S4: `save_nodes_config` 无校验 → 恶意节点注入

- **位置**: `openwire/src-tauri/src/lib.rs:638-658`
- **风险**: multiaddr 字符串直接存储，重启后连接恶意节点，可被 MITM 或 de-anonymize
- **修复**: 使用 `Multiaddr::try_from` 验证格式；校验 peer_id 长度

#### S5: `log.rs` `.expect()` panic → DoS

- **位置**: `openwire_core/src/log.rs:88,103`
- **风险**: 日志目录不可写时 `.expect()` 直接 panic，导致整个进程崩溃
- **修复**: 改为 `?` 传播错误：
  ```rust
  std::fs::create_dir_all(path)
      .map_err(|e| LogError::CreateDirFailed(e.into()))?;
  ```

#### S6: `validate_mldsa_pubkey_hex` 接受空字符串

- **位置**: `openwire_core/src/signature.rs:23-45`
- **风险**: 空字符串通过验证，后续 DHT 操作使用空密钥导致静默失败
- **修复**: 增加长度检查：
  ```rust
  if hex.is_empty() || hex.len() != ML_DSA_65_PUBLIC_KEY_HEX_LEN {
      return false;
  }
  ```

### 2.2 高危 — 加密与身份相关

#### S7: DHT 身份绑定缺失 → 身份冒充

- **位置**: `openwire_core/src/message/mod.rs:169-178`、`openwire_core/src/p2p/events.rs:155-159`
- **风险**: 代码注释明确说明"不验证 sender_public_key 是否与 DHT 注册身份绑定一致"。攻击者可用自己密钥签名消息，声称是任意联系人
- **修复方案 A（推荐）**: 在 `handle_incoming_request` 中增加 DHT 绑定验证：
  ```rust
  // 验证 sender_public_key 与 DHT 注册身份一致
  let store = core.get_dht_store();
  let registered_pubkey = store.get_pubkey_by_peerid(&peer)
      .ok_or_else(|| P2pError::IdentityBindingNotFound)?;
  if !constant_time_compare(&request.sender_public_key, &registered_pubkey) {
      return; // 拒绝冒充消息
  }
  ```
- **修复方案 B**: 消息签名中加入 `sender_public_key` 的 DHT 记录签名，接收方验证 DHT 记录签名

#### S8: DHT ML-KEM 密钥未认证 → MITM

- **位置**: `openwire_core/src/actor/p2p/swarm_ops.rs:96-101`
- **风险**: ML-KEM 公钥的 DHT 记录 `publisher: None`，无签名，任意节点可覆盖他人密钥
- **修复**: 设置 `publisher: Some(self_peer_id)` 并使用 libp2p 签名记录；读取时验证签名

#### S9: 1 小时消息重放窗口

- **位置**: `openwire_core/src/message/mod.rs:15-17,200-211`
- **风险**: 仅有时戳范围检查，无 per-message 去重。同一消息可在 1 小时内重复发送
- **修复**: 增加 LRU 缓存记录最近收到的消息哈希，拒绝重复：
  ```rust
  // 使用 lru::LruCache 或简单 HashSet（限制容量）
  if !self.seen_hashes.insert(message_hash) {
      return; // 重复消息，丢弃
  }
  ```

### 2.3 高危 — 密钥存储相关

#### S10: Master Key 直接用作 AES 密钥（无 KDF）

- **位置**: `rootcell/src/identity.rs:187-188`
- **风险**: 32 字节 master key 直接作为 AES-256-GCM 密钥，无 HKDF 派生。keyring 泄露即可解密所有身份文件
- **修复**:
  ```rust
  use hkdf::Hkdf;
  use sha2::Sha256;
  
  let hk = Hkdf::<Sha256>::new(Some(b"openwire-key-derivation"), &master_key);
  let mut aes_key = [0u8; 32];
  hk.expand(identifier.as_bytes(), &mut aes_key)
      .map_err(|_| anyhow::anyhow!("HKDF expand failed"))?;
  let key = Key::<Aes256Gcm>::from(aes_key);
  ```

#### S11: Master Key 未 Zeroize

- **位置**: `rootcell/src/identity.rs:107-109`
- **风险**: `load_master_key()` 返回普通 `[u8; 32]`，函数返回后密钥残留在栈上，内存转储可恢复
- **修复**:
  ```rust
  use zeroize::Zeroizing;
  
  pub fn load_master_key() -> anyhow::Result<Option<Zeroizing<[u8; 32]>>> {
      // ...
      let mut key = Zeroizing::new([0u8; 32]);
      key.copy_from_slice(&decoded);
      Ok(Some(key))
  }
  ```

#### S12: rootcell `data_dir` 路径遍历

- **位置**: `rootcell/src/identity.rs:184,170`
- **风险**: `data_dir` 未规范化，包含 `..` 时可写入任意路径
- **修复**:
  ```rust
  let data_dir = std::fs::canonicalize(data_dir)
      .map_err(|e| anyhow::anyhow!("无效的 data_dir: {}", e))?;
  let keys_dir = data_dir.join("keys");
  ```

#### S13: `delete_master_key` 在任何错误时删除凭据

- **位置**: `rootcell/src/identity.rs:155-159`
- **风险**: 临时 keyring 不可用时删除 master key，所有身份文件不可恢复
- **修复**:
  ```rust
  Err(e) => {
      tracing::error!("检查 master key 失败: {e:?}");
      Err(anyhow::anyhow!("Keyring 不可用，无法删除 master key: {e}"))
  }
  ```

## 三、误报说明

| 原发现 | 误报原因 |
|--------|----------|
| `request_file_download` 路径遍历 | `resolve_download_dir` 在 `file_transfer.rs:65-105` 中做了规范化 + 沙箱检查，超出 `data_dir` 的路径会回退到 `downloads_dir` |
| 分片偏移整数溢出 | `saturating_mul` 在溢出时钳位到 `u64::MAX`，而非回绕，非法 offset 不会匹配 |

## 四、修复优先级

### 第 1 优先级（立即修复）— 可被远程利用

```
S1  send_file 任意文件读取     高危-远程

S7  DHT 身份冒充               高危-远程
S8  DHT ML-KEM MITM            高危-远程

```

```
S5  log.rs panic/DoS            高危-本地
S6  空公钥验证通过              中危-本地
```

### 第 3 优先级（短期修复）— 密钥存储加固

```
S10 Master Key 无 KDF           高危-本地
S11 Master Key 未 Zeroize       高危-本地
S12 data_dir 路径遍历           高危-本地

```
